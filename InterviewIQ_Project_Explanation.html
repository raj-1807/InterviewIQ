1. Project Overview

InterviewIQ is a production-ready, SaaS-style AI interview preparation platform built with the MERN stack. It allows users to:

  • Upload their resume (PDF) and have AI extract and analyze the content
  • Practice with AI-generated interview questions (technical, behavioral, HR) personalized to their resume and target job role
  • Get real-time AI feedback on each answer with scores from 0-10
  • Receive an overall assessment with strengths, improvements, and a score out of 100
  • Purchase credits via Razorpay to access more interview sessions
  • Login securely using Google Authentication through Firebase
💡 Key Differentiator
Unlike basic CRUD apps, this project demonstrates real-world patterns: third-party API integration (Gemini AI, Firebase, Razorpay), credit-based monetization, PDF processing, and a chat-style interactive UI.

5. Backend — Step by Step

5.1 Server Entry Point (index.js)

The server initializes Express, connects to MongoDB, configures middleware (CORS, JSON parsing, cookie-parser), and registers all API routes.

import express from 'express';
import connectDB from './config/db.js';

const app = express();

// Connect to MongoDB Atlas
connectDB();

// Middleware
app.use(cors({ origin: process.env.CLIENT_URL, credentials: true }));
app.use(express.json());
app.use(cookieParser());

// Routes
app.use('/api/auth', authRoutes);
app.use('/api/interview', interviewRoutes);
app.use('/api/payment', paymentRoutes);

5.2 Authentication Flow

We use a dual authentication approach:

  1. Firebase Auth on the client handles Google Sign-In and gives us a Firebase ID Token
  2. Backend verifies the Firebase token using Firebase Admin SDK
  3. Backend creates a JWT for subsequent API calls (stored in HTTP-only cookie)
// 1. Client sends Firebase token to backend
const decodedToken = await admin.auth().verifyIdToken(token);

// 2. Find or create user in MongoDB
let user = await User.findOne({ firebaseUid: uid });
if (!user) user = await User.create({ name, email, firebaseUid: uid, credits: 5 });

// 3. Generate JWT for our own API
const jwtToken = jwt.sign({ id: user._id }, process.env.JWT_SECRET, { expiresIn: '7d' });

// 4. Set HTTP-only cookie
res.cookie('token', jwtToken, { httpOnly: true, secure: true });

5.3 Interview Flow (AI Integration)

The interview process has 3 main API calls:

Step 1: Start Interview

  • User uploads PDF resume + enters job role
  • Multer handles file upload (memory storage, 5MB limit)
  • pdf-parse extracts text from the PDF buffer
  • Text is sent to Gemini AI with a structured prompt to generate 10 questions
  • 1 credit is deducted from the user's account

Step 2: Submit Answer

  • For each question, the user's answer is sent to Gemini AI
  • AI evaluates and returns a score (0-10) + detailed feedback
  • Result is saved to the interview document in MongoDB

Step 3: Complete Interview

  • After all questions are answered, Gemini AI generates overall feedback
  • Returns: overall score (0-100), strengths, areas for improvement

5.4 Payment Integration (Razorpay)

Payment follows the standard Razorpay server-to-server flow:

  1. Create Order: Backend creates a Razorpay order using their SDK
  2. Client Checkout: Frontend opens the Razorpay payment popup
  3. Verify Payment: Backend verifies the payment signature using HMAC-SHA256
  4. Grant Credits: On successful verification, credits are added to the user
// Signature verification (critical for security)
const body = razorpay_order_id + '|' + razorpay_payment_id;
const expectedSignature = crypto
    .createHmac('sha256', process.env.RAZORPAY_KEY_SECRET)
    .update(body)
    .digest('hex');

if (expectedSignature !== razorpay_signature) {
    throw new Error('Payment verification failed');
}

6. Frontend — Step by Step

6.1 State Management (Redux Toolkit)

We use Redux Toolkit with two slices:

  • userSlice: Manages authentication state (user object, JWT token, credits). Persists to localStorage so login survives page refresh.
  • interviewSlice: Manages current interview session and history.

6.2 API Layer (Axios Interceptors)

A centralized Axios instance with two interceptors:

  • Request interceptor: Automatically attaches the JWT token from localStorage to every request's Authorization header.
  • Response interceptor: On 401 errors, clears auth state and redirects to login page.

11. Interview Q&A (30+ Questions)

🏗️ Architecture & Design

1What is the overall architecture of this project?
It follows a 3-tier architecture: React frontend (Presentation), Express.js backend (Business Logic), and MongoDB (Data). The frontend communicates with the backend via REST APIs. The backend integrates with 3 external services: Firebase (auth), Google Gemini (AI), and Razorpay (payments). Authentication uses a dual approach — Firebase handles Google Sign-In on the client, then the backend verifies the Firebase token and issues its own JWT for API authorization.
2Why did you choose the MERN stack?
MERN (MongoDB, Express, React, Node) provides JavaScript across the entire stack, simplifying development. MongoDB's flexible document model is ideal for storing nested interview data (questions, answers, feedback all in one document). React's component model allows building a complex interactive UI like the chat-style interview. Node.js handles async operations (AI API calls, file processing) efficiently via its event loop.
3Why use Firebase Auth instead of building your own authentication?
Firebase Auth provides battle-tested OAuth integration (Google, GitHub, etc.) with minimal code. It handles token management, session persistence, and security automatically. Building OAuth from scratch requires handling redirects, token exchange, PKCE flows, and security vulnerabilities — Firebase eliminates all of this. We still use our own JWT for API authorization to keep backend logic independent of Firebase.
4Why dual authentication (Firebase + JWT)?
Firebase tokens are tied to Firebase's infrastructure. By issuing our own JWT after verifying the Firebase token, we: (1) decouple our API from Firebase — if we switch auth providers, only the login endpoint changes, (2) control token expiry and payload, (3) can add custom claims like user ID from our database, (4) reduce latency — JWT verification is a simple cryptographic check vs. Firebase's network call.

🔧 Backend Questions

5How does the JWT middleware work?
The auth middleware extracts the JWT from either cookies (req.cookies.token) or the Authorization header (Bearer token). It verifies the token using jwt.verify() with the secret key. If valid, it fetches the user from MongoDB using the decoded id and attaches it to req.user for downstream handlers. If invalid/expired, it returns a 401 error.
6How does the resume upload work technically?
Multer is configured with memoryStorage(), meaning the file is stored in RAM as a Buffer (not written to disk). A custom fileFilter only allows .pdf files. The 5MB limit is enforced via limits.fileSize. The buffer is then passed to pdf-parse, which extracts the text content from the PDF binary without needing a file system write.
7Why use memory storage for Multer instead of disk?
We only need the PDF's text content, not the file itself. Memory storage avoids disk I/O, is faster, and doesn't require cleanup. The buffer is processed immediately by pdf-parse and then garbage collected. For a production app handling large files, you'd use disk storage or cloud storage (S3), but for our 5MB PDFs, memory is efficient.
8How do you ensure the AI returns valid JSON?
Three safeguards: (1) The prompt explicitly instructs: "Return ONLY valid JSON, no markdown, no code blocks, no extra text". (2) The parseAIResponse() helper strips markdown code block wrappers (```json...```) if the AI adds them. (3) A try-catch wraps the parse — if it fails, we provide a sensible fallback (e.g., default score of 5) rather than crashing.
9How is the Razorpay payment verified securely?
Razorpay uses HMAC-SHA256 signature verification. After payment, Razorpay returns 3 values: order_id, payment_id, and a signature. The backend concatenates order_id + "|" + payment_id, generates an HMAC using the Razorpay secret key, and compares it with the provided signature. If they match, the payment is genuine and hasn't been tampered with. Only then are credits granted.
10Why do you create a Payment record before the payment is made?
We create the record with status: "created" when generating the Razorpay order. This provides audit trail and idempotency. If the user's browser crashes after payment but before verification, we still have the order record. We can reconcile using Razorpay's webhook or dashboard. The status updates to "paid" only after successful verification.
11What happens if the user has 0 credits and tries to start an interview?
The backend checks user.credits <= 0 before proceeding. It returns a 403 Forbidden response with the message "Insufficient credits. Please purchase more." The frontend shows this error and displays a link to the pricing page. No interview document is created and no AI API call is made.
12How do you handle CORS?
The backend configures CORS with: origin: process.env.CLIENT_URL (restricts to our frontend domain), and credentials: true (allows cookies to be sent cross-origin). In development, the Vite proxy at /api also sidesteps CORS issues since the browser sees same-origin requests.

⚛️ Frontend Questions

13Why Redux Toolkit instead of Context API?
Redux Toolkit offers: (1) Predictable state with a single store and immutable updates via Immer, (2) DevTools for time-travel debugging, (3) Better scalability — as the app grows with more features (notifications, settings), adding slices is clean, (4) Middleware support — for logging, async thunks, etc. Context API would cause unnecessary re-renders in deeply nested components like the interview chat.
14How do you persist user login across page refresh?
The Redux userSlice reads initial state from localStorage. When a user logs in, both the user object and JWT token are saved to localStorage. The slice's initialState does: user: JSON.parse(localStorage.getItem('user')). On page refresh, Redux rehydrates from localStorage. The JWT in the HTTP-only cookie also persists, so API calls continue to work.
15What are Axios interceptors and how do you use them?
Request interceptor: Before every API call, it reads the JWT from localStorage and adds it as Authorization: Bearer <token> header. This avoids repeating auth logic in every API call. Response interceptor: On 401 responses, it clears localStorage and redirects to /login, handling token expiry globally without per-component logic.
16How does the ProtectedRoute component work?
It's a wrapper component that checks useSelector(state => state.user.user). If no user exists in Redux state, it renders <Navigate to="/login" replace /> which redirects without adding to browser history. If a user exists, it renders the {children}. This pattern is called a route guard or higher-order component (HOC) pattern.
17How do you handle the chat-style interview UI?
The Interview page maintains a feedbackHistory state array. Each completed Q&A is pushed into this array and rendered as alternating "AI question" and "user answer" bubbles (like a chat). The current question is shown separately with a glowing animation. A useRef + scrollIntoView auto-scrolls to the latest message. AnimatePresence from Framer Motion adds enter/exit animations.
18What is the Vite proxy and why is it needed?
In development, the frontend runs on :5173 and backend on :8000. Making API calls from :5173 to :8000 is cross-origin. The Vite proxy rewrites /api/* requests to http://localhost:8000/api/* at the dev server level, so the browser sees same-origin requests. This avoids CORS issues in development. In production, both would be served from the same domain.
19How does the animated circular score work on the Results page?
It uses SVG with stroke-dasharray and stroke-dashoffset. A circle is drawn with a circumference of 2πr. The dashoffset controls how much of the circle is visible. Framer Motion's motion.circle animates the dashoffset from full (hidden) to the calculated value based on score percentage, creating the fill-up animation. The score text is positioned absolutely in the center.

🔐 Security Questions

20How do you prevent CSRF attacks?
Multiple layers: (1) JWT is stored in an HTTP-only cookie with SameSite attribute, preventing cross-site cookie sending, (2) CORS is restricted to our frontend origin only, (3) The JWT is also sent via Authorization header (which can't be set by cross-site forms), (4) Razorpay uses HMAC signature verification for payment callbacks.
21Why HTTP-only cookies for JWT?
HTTP-only cookies cannot be accessed by JavaScript (document.cookie won't see them). This prevents XSS attacks from stealing the token. If an attacker injects a script, they can't read the JWT. We also store the token in localStorage for the Authorization header (a tradeoff for SPA convenience), but the cookie serves as the primary secure channel.
22How do you validate file uploads?
Three validation layers: (1) File type filter: Multer's fileFilter checks the extension is .pdf, (2) Size limit: limits.fileSize: 5 * 1024 * 1024 rejects files over 5MB, (3) Server-side processing: The file never touches the disk — processed in memory and discarded. We don't serve uploaded files back to users, eliminating path traversal risks.

📊 Database & Performance

23Why embed questions inside the Interview document instead of a separate collection?
Questions belong exclusively to one interview — there's no need to query them independently. Embedding avoids JOIN-like operations (populate). When we load an interview, we get all questions in a single read. MongoDB's document model is designed for this. The subdocument approach also provides atomicity — updating a question's score and the interview's progress happens in one save().
24How would you scale this application for 10,000+ users?
Several approaches: (1) MongoDB Atlas auto-scaling with sharding on userId, (2) Redis caching for user credits and frequent reads, (3) Queue system (Bull/RabbitMQ) for AI processing — instead of synchronous Gemini calls, queue requests and poll for results, (4) Rate limiting on API endpoints, (5) CDN for the React build, (6) Horizontal scaling with PM2 cluster mode or Kubernetes.
25What indexes would you add for performance?
Key indexes: (1) User.email — unique, used in login lookup, (2) User.firebaseUid — unique, used in auth verification, (3) Interview.userId + createdAt — compound index for history queries sorted by date, (4) Payment.orderId — used in payment verification lookup. Mongoose automatically creates an index on _id and unique fields.

🤖 AI & Prompt Engineering

26Why Google Gemini 2.0 Flash instead of GPT-4?
Gemini 2.0 Flash offers: (1) Fast inference — "Flash" models prioritize speed, ideal for real-time Q&A, (2) Cost-effective — significantly cheaper than GPT-4 for structured tasks, (3) Google ecosystem — easy integration with the official @google/generative-ai SDK, (4) Good enough — for interview question generation and answer evaluation, we don't need GPT-4's reasoning depth. The architecture is provider-agnostic — switching to OpenAI requires changing only config/gemini.js.
27How do you handle AI hallucinations or bad responses?
Multiple safeguards: (1) Structured prompts — we specify exact JSON format, reducing free-form output, (2) JSON parsing in try-catch — if parsing fails, we provide fallback values (default score of 5, generic feedback), (3) Score clamping: Math.min(10, Math.max(0, score)) ensures scores stay in range even if AI returns outliers, (4) Prompt includes "return ONLY JSON" — repeated instruction reduces non-JSON output.
28What is prompt engineering and how did you use it here?
Prompt engineering is crafting input text to guide AI behavior. We use three techniques: (1) Role assignment — "You are an expert technical interviewer", (2) Output format specification — exact JSON structure with examples, (3) Context injection — resume text + job role provide personalization. The question generation prompt specifies the mix (6 technical + 2 behavioral + 2 HR) for diversity.

31What challenges did you face and how did you solve them?
Key challenges: (1) AI response parsing — Gemini sometimes wraps JSON in markdown code blocks. Solution: regex-based stripping before JSON.parse. (2) PDF text extraction — pdf-parse's default import causes ESM issues. Solution: import from pdf-parse/lib/pdf-parse.js directly. (3) Real-time chat feel — maintaining scroll position and smooth animations while updating state. Solution: useRef + scrollIntoView + AnimatePresence.

33Explain the credit system — how is it different from a subscription model?
Our credit-based (pay-per-use) model is like tokens: each interview costs 1 credit, and users buy credit packs (10 for ₹99, 25 for ₹199, 60 for ₹399). Benefits over subscription: (1) No recurring charges — users pay only when they need, (2) Lower barrier — 5 free credits let users try without commitment, (3) Volume discounts — bigger packs have lower per-credit cost, incentivizing bulk purchases. Credits never expire, stored as a simple integer in the User document.
34What is Glassmorphism and why did you use it?
Glassmorphism is a UI design trend featuring: frosted glass-like backgrounds using backdrop-filter: blur(), semi-transparent surfaces, subtle borders, and depth via layering. We used it because: (1) It creates a premium, modern feel appropriate for a SaaS product, (2) The translucent layers provide visual hierarchy, (3) Combined with our dark theme and glow effects, it creates an immersive experience. CSS: background: rgba(26,26,62,0.6); backdrop-filter: blur(20px);
35How does Express.js middleware chain work in this project?
Middleware executes in order: (1) CORS → validates origin, (2) express.json() → parses JSON body, (3) cookieParser() → parses cookies, (4) Route-level middleware: auth (JWT check) → upload.single('resume') (file processing) → controller function. Each calls next() to pass control. If any middleware returns a response (like 401), the chain stops. Error middleware at the end catches unhandled errors.
